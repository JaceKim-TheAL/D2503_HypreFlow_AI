## 하이퍼플로우 핵심 개념: AI 애플리케이션 개발자를 위한 입문 가이드
HyperFlow는 AI 애플리케이션의 구축, 배포, 관리를 혁신적으로 바꿔 줄 **노코드/로우코드 플랫폼**입니다. <br/>시각적 프로그래밍의 직관성과 최첨단 AI 기술을 결합하여, 기술자와 비전문가 모두가 손쉽게 고급 AI 애플리케이션을 개발할 수 있도록 지원합니다.

### 왜 하이퍼플로우여야 할까요?

**문제점:** 고도화된 AI 애플리케이션을 구축하려면, 일반적으로 방대한 코딩 지식, 다양한 AI 기술에 대한 깊은 이해, 복잡한 인프라 관리 역량이 요구됩니다.

**해결책:** HyperFlow의 시각적 플로우 그래프 환경은 이러한 복잡함을 제거하고, 사용자가 정말 중요한 일 `현실의 문제를 해결하는 강력한 AI 애플리케이션 개발` 에 집중할 수 있도록 도와줍니다.

### 핵심 개념

### 1. 플로우 그래프 패러다임
HyperFlow의 중심에는 **플로우 그래프**가 있습니다 — AI 애플리케이션의 로직을 시각적으로 표현한 구조입니다.
- **노드(Node)**: 특정 작업을 수행하는 기본 단위입니다 (예: LLM 호출, 데이터 처리 등)
- **엣지(Edge)**: 노드 간 연결로, 실행 흐름(프로세스 플로우)과 데이터 흐름을 모두 나타냅니다
- **파라미터(Parameter)**: 각 노드의 동작을 설정하는 구성 요소입니다
<br/>

HyperFlow의 플로우 그래프 시스템이 특별한 이유:
- **통합형 그래프 구조**: 프로세스 흐름과 데이터 흐름을 하나의 환경에서 통합 관리
- **동적 제어 흐름**: 반복(loop), 분기(branch), 조건 경로 등을 유연하게 표현
- **강한 데이터 타입 지원**: 노드 간 연결 호환성을 보장하고, 지능적인 데이터 처리 가능
- **실행 기록 추적**: 디버깅과 최적화를 위한 전체 실행 이력 저장
<br/>

### 2. 슈퍼 노드와 서비스 아키텍쳐
HyperFlow의 혁신적인 **슈퍼 노드(Super Node)** 아키텍처는 복잡도를 높이지 않고도 구축할 수 있는 범위를 획기적으로 확장시켜줍니다.
- **추상화된 서비스**: 노드는 "어떻게"가 아닌, "무엇을 할 것인가"를 정의합니다
- **다중 구현 지원**: 하나의 노드가 여러 서비스 제공자와 연결될 수 있습니다
- **일관된 인터페이스**: 어떤 구현을 사용하든 입력과 출력 형식은 동일하게 유지됩니다
- **간편한 테스트**: LLM 제공자 등 다양한 서비스를 드롭다운으로 손쉽게 전환하며 테스트할 수 있습니다

예를 들어, **Call LLM** 노드는 OpenAI, Anthropic, Google AI 등 다양한 AI 서비스와 연결할 수 있으며, 플로우 그래프의 구조를 변경할 필요가 없습니다.
<br/>

### 3. 하이퍼파라메트릭스 엔진
HyperFlow의 파라미터 시스템은 단순한 설정을 넘어 훨씬 더 강력한 기능을 제공합니다.
- **인터랙티브 구성**    
    직관적인 파라미터 패널을 통해 노드를 시각적으로 설정할 수 있습니다.
    
- **23가지 파라미터 타입**    
    단순한 드롭다운부터 복잡한 JSON 구조까지 다양하게 지원합니다.
    
- **조건 기반 의존성**    
    선택한 값에 따라 파라미터 항목이 동적으로 나타나거나 변경됩니다.
    
- **이중 모드 파라미터**    
    개발 중에 수동으로 설정하거나, 실행 시 동적으로 제어되도록 연결할 수 있습니다.
    
이 시스템은 빠른 프로토타이핑은 물론, 복잡한 동적 애플리케이션에도 유연하게 대응할 수 있도록 설계되었습니다.
<br/>

### 4. 이중 엔진 아키텍쳐
HyperFlow는 두 가지 특화된 플로우 그래프 실행 엔진을 제공합니다:

- **개발용 엔진** – 생성 및 테스트 단계에서 사용
    - 단일 스텝 실행 및 브레이크포인트 기반의 인터랙티브 디버깅
    - 실시간 파라미터 조정
    - 테스트를 위한 내장 챗봇 시뮬레이터
    - 전체 실행 이력 추적 기능
- **프로덕션용 엔진** – 실제 배포 환경에서 사용
    - 프로덕션 워크로드에 최적화된 성능
    - 외부 제어를 위한 RESTful API 제공
    - 활성 세션을 중단하지 않고도 핫픽스 적용 가능
    - 실행 무결성을 보장하는 Run-Clone 시스템 지원

## 핵심 구성 요소

### LLM 상호작용 노드
- **Call LLM**: 텍스트 생성을 위한 기본 노드로, 다음과 같은 기능을 지원합니다:
    - 텍스트, 이미지, 오디오, 비디오를 포함한 멀티모달 처리
    - LLM 제공자 동적 선택
    - 고급 프롬프트 엔지니어링
    - 지식 주입 및 참조 추적 기능
- **‘Call LLM with Tools’ 노드**:    
    도구 기반 LLM을 위한 특수 노드로, 복잡한 에이전트형 워크플로우를 구현할 수 있습니다.
    

### 콘텐츠 처리

- **Import Content (콘텐츠 가져오기 노드)**    
    문서, 웹사이트, 데이터를 애플리케이션으로 가져옵니다.
    
- **Transform Content (콘텐츠 변환 노드)**    
    다양한 변환기를 사용해 콘텐츠를 가공하고 처리합니다.
    
- **Segmentation Nodes (콘텐츠 분할 노드)**    
    지식베이스에 최적화된 형태로 콘텐츠를 분할하며, PDF, HTML, 텍스트 등 형식별 특화 노드를 제공합니다.
    

### 지식베이스 관련 노드

- **Create Embedding Vectors (임베딩 생성 노드)**    
    텍스트를 임베딩 벡터로 변환합니다.
    
- **Create Knowledge DB (지식 DB 생성 노드)**    
    생성된 임베딩을 기반으로 검색 가능한 벡터 지식베이스를 구축합니다.
    
- **Search Knowledge DB (지식 DB 검색 노드)**    
    벡터 지식베이스에서 유사도 기반 검색을 수행합니다.
    
- **Re-rank (순위 재조정 노드)**    
    고급 재정렬 알고리즘을 통해 검색 결과의 정확도를 향상시킵니다.
    

### 데이터 흐름 및 제어 관련 노드

- **Data Transform (데이터 변환 노드)**    
    템플릿 또는 Python 코드를 활용해 데이터를 변환하는 다기능 노드입니다. *(플로우 그래프의 맥가이버 칼!)*
    
- **Match and Branch (매칭 & 메시지 노드)**    
    조건에 따라 분기되는 경로와 의사결정 트리를 구성합니다.
    
- **Loop Controller (루프 제어 노드)**    
    반복이 필요한 작업을 위한 루프 실행 구조를 구현합니다.
    
- **Key-Value Store (키값 저장소 노드)**    
    세션 간에도 유지되는 상태 정보를 저장하고 관리합니다.
    

### 통합 노드

- **URL Access (URL 접근 노드)**    
    웹사이트에서 콘텐츠를 가져옵니다.
    
- **Web Search (웹 검색 노드)**    
    플로우 내에서 웹 검색을 수행할 수 있습니다.
    
- **Python Code (파이선 노드)**
    특수한 작업을 위해 사용자 정의 Python 코드를 실행합니다.
    

## 실전 예제 : RAG 애플리케이션 만들기

앞서 소개한 개념들을 바탕으로, 다음은 **검색 기반 생성(RAG, Retrieval-Augmented Generation)** 애플리케이션을 구축하는 방법입니다:

1. **Import Content** (콘텐츠 가져오기 노드)를 사용해 PDF 문서를 가져옵니다.
2. **Segment PDF (PDF 분할 노드)** 로 문서를 적절한 크기로 분할합니다.
3. **Create Embedding Vectors (임베딩 생성 노드)** 를 통해 임베딩 벡터를 생성합니다.
4. **Create Knowledge DB (지식 DB 생성 노드)** 로 검색 가능한 지식베이스를 구축합니다.
5. 사용자의 질문이 들어오면, **Search Knowledge DB (지식 DB 검색 노드)** 로 관련 정보를 검색합니다.
6. **Re-rank (순위 재조정 노드)** 를 사용해 검색 결과의 관련도를 향상시킵니다.
7. 마지막으로 **Call LLM(LLM 호출 노드)** 을 통해 일관되고 지식이 반영된 응답을 생성합니다.

이 전체 애플리케이션은 **단 한 줄의 코드도 작성하지 않고** 시각적으로 구성할 수 있습니다. (물론, Python으로 더욱 커스터마이징도 가능합니다.)
<br/>

## 하이퍼플로우로 개발 시 장점

- **빠른 개발 속도**     
    몇 주가 걸리던 고급 AI 애플리케이션을 몇 시간 만에 구축할 수 있습니다.
    
- **유연성**    
    애플리케이션을 다시 만들지 않고도 다양한 AI 서비스를 자유롭게 실험할 수 있습니다.
    
- **확장성**    
    단순한 챗봇부터 복잡한 멀티 에이전트 시스템까지 유연하게 대응합니다.
    
- **미래 대응력**    
    새로운 AI 서비스가 출시되어도 기존 애플리케이션에 손쉽게 통합할 수 있습니다.
    
- **높은 접근성**    
    개발자뿐 아니라 비개발자도 함께 참여하고 기여할 수 있습니다.
    

## 시작하기
HyperFlow로 첫 번째 AI 애플리케이션을 만들어볼 볼까요?

1. **인터페이스 탐색하기**    
    에디터, 브라우저, 시뮬레이터 뷰의 구성과 기능을 확인해보세요.
    
2. **프로젝트 생성하기**    
    조직 계정에서 새 프로젝트를 생성하세요.
    
3. **API 키 설정하기**    
    API 구성 섹션에서 사용할 AI 서비스의 API 키를 추가하세요.
    
4. **플로우 만들기 시작**    
    캔버스에 노드를 끌어다 놓고 연결하여 플로우를 구성하세요.
    
5. **테스트 및 개선**    
    시뮬레이터를 사용해 애플리케이션을 테스트하고 반복적으로 개선하세요.

## 플로우 그래프 설계를 위한 핵심 원칙

- **단순하게 시작하기**    
    기본적인 플로우부터 시작해 단계적으로 확장해보세요.
    
- **자주 테스트하기**    
    빌드 중에도 시뮬레이터를 활용해 플로우를 수시로 테스트하세요.
    
- **자유롭게 실험하기**    
    다양한 서비스를 손쉽게 교체하며 결과를 비교해보세요.
    
- **모듈화하기**    
    복잡한 작업은 하위 플로우로 나누어 관리하기 쉽게 만드세요.
    
- **실행 이력 확인하기**
    
    실행 기록을 분석해 플로우의 동작을 이해하고 최적화하세요.
    

## 고급 기능 살펴보기

HyperFlow의 핵심 개념에 익숙해졌다면, 이제 다음과 같은 고급 기능들을 활용해보세요:

- **Python 변환 기능**    
    사용자 정의 코드를 통해 플로우를 확장할 수 있습니다.
    
- **에이전트 기반 시스템**    
    도구를 활용하는 LLM을 활용해 멀티 에이전트 워크플로우를 구성할 수 있습니다.
    
- **복잡한 의사결정 트리**    
    정교한 조건 분기 로직을 구현할 수 있습니다.
    
- **상태 유지형 애플리케이션**    
    세션 간에도 대화 맥락을 유지하는 애플리케이션을 만들 수 있습니다.
    
- **멀티모달 애플리케이션**    
    텍스트, 이미지, 오디오, 비디오 처리를 결합한 복합형 앱을 구성할 수 있습니다.

## 플로우 그래프란

이번엔 **HyperFlow 개발 플랫폼**의 기본 개발 요소인 **플로우 그래프**를 소개하도록 하겠습니다.

HyperFlow는 시각적으로 로직을 설계하여 AI 애플리케이션과 워크플로우를 만드는 **노코드 환경**을 제공합니다. 코드 작성 없이 애플리케이션의 프로세스를 나타내는 **플로우 그래프**를 함께 살펴보겠습니다. HyperFlow 개발 환경은 이러한 시각적 표현을 구현하고 이를 실행하면서 실시간으로 함께 개선하는 할 수 있도록 구축되었습니다.

플로우 그래프는 HyperFlow에서 애플리케이션을 구축하는 거의 모든 상황에 사용됩니다. 챗봇 개발, 지식 베이스용 콘텐츠 가져오기 및 처리, 외부 서비스와의 통합, 여러 AI 모델이 협업하는 에이전트 워크플로우 설정, HyperFlow의 제어 및 API 플러그인 시스템을 통한 여러 독립적인 서비스 조율 등에 사용할 수 있습니다. HyperFlow는 이러한 플로우 그래프 기반 시스템을 제공하여, 복잡한 복합 AI 시스템 구축을 쉽게 구현 할 수 있는 훌륭한 허브가 되고자 합니다.

**플로우 그래프 예제**

플로우 그래프에 대한 이해를 돕기 위해, 먼저 첫 프로젝트와 함께 자동으로 설치되는 예제들을 살펴보겠습니다. 예제들은 개발 환경 왼쪽의 **플로우 그래프 디렉토리**에 위치해 있습니다. 이 디렉토리는 현재 프로젝트 내의 모든 플로우 그래프를 보여줍니다. "Examples" 태그 아래에 그룹화된 예제들은 6-7개의 서로 다른 워크플로우를 보여주며, 다양한 응용 사례를 제시합니다. 각각의 목적과 구조를 설명과 함께 살펴봅시다.

### **예제 1:  단순 원샷(One-shot) 챗봇**

원하는 플로우 그래프를 디렉토리에서 선택하면, 그래프가 에디터에 나타납니다. 가장 기본적인 플로우 그래프인 단순 원샷 챗봇부터 살펴보겠습니다.

![image.png](https://prod-files-secure.s3.us-west-2.amazonaws.com/b70dea2a-0f0a-44d5-ae81-89a1124d77c1/a2b809f2-d787-4574-872e-30420c382704/image.png)

이 플로우 그래프에는 **노드**라고 불리는 두 개의 구성 요소만 있습니다. 각 노드는 워크플로우의 특정 단계로, 첫 번째 노드가 실행된 후 두 번째 노드가 실행됩니다. **보라색 선**은 실행 순서를 보여주며 **프로세스 흐름**을 정의합니다. **파란색 선**은 **데이터 흐름**을 보여주며 노드 간 데이터 이동 방식을 정의합니다.

이 플로우 그래프에서 첫 번째 노드는 프롬프트나 쿼리와 같은 사용자 입력을 요청합니다. 보라색 선은 그 다음 흐름을 두 번째 노드인 **대규모 언어 모델(LLM)** 호출로 진행합니다. 노드 사이의 파란색 선은 사용자 입력이 LLM으로 전달되는 것을 보여줍니다. LLM은 프롬프트를 처리하고 응답을 생성한 후 이를 표시합니다.

이 두 노드 구조는 "원샷" 챗봇을 만듭니다. 사용자가 입력을 제공하면 LLM이 단일 응답을 생성합니다

이를 바탕으로 다음 예제들인 루핑(looping) 챗봇과 지식 기반 챗봇을 살펴보도록 하겠습니다. 

### **예제 2: 루핑(Looping) 챗봇**

원샷 챗봇을 기반으로 **루핑 챗봇**을 구현하면 더욱 동적인 상호작용이 가능한 챗봇을 만들 수 있습니다.

![image.png](https://prod-files-secure.s3.us-west-2.amazonaws.com/b70dea2a-0f0a-44d5-ae81-89a1124d77c1/76b5672b-11a2-4aaa-a1ed-438f9fad0f38/image.png)

앞선 예제1과 비교 시, 예제2의 플로우 그래프에는 중요한 부분이 추가되어있습니다: 보라색 선으로 표시되는 프로세스 흐름이 이제 LLM 호출 후에 다시 루프백됩니다. 이 루프는 ChatGPT나 Gemini에서 동작하는 챗봇처럼, 지속적인 대화를 가능하게 합니다.

루프 외에 다른 노드도 추가되었습니다. 가장 위에 보이는 새로운 노드는 LLM 호출에 **지시사항**을 입력 할 수 있게 합니다. 이러한 지시사항은 LLM이 사용자 요청에 어떻게 행동하고 응답해야 하는지 안내하며, 이는 일반적으로 "프롬프트 엔지니어링"이라고 불리는 중요한 측면입니다.

또한 데이터 흐름 루프가 추가되어 LLM의 응답을 다시 `이전 응답` 입력으로 피드백합니다. 이는, LLM이 일반적으로 장기 기억력이 없기 때문에, 앞선 대화의 내용을 기반으로 대화 하기 위해선 필수로 추가해야 합니다. 문맥을 유지하기 위해 애플리케이션은 대화 기록을 유지하고 각 실행 기록을 LLM에 전달해야 합니다. 이를 통해 LLM에 필요한 대화 문맥을 제공합니다.

### **예제 3: 지식 기반 챗봇**

이번 예제는 특정 정보를 기반으로 문맥적으로 관련된 응답을 제공하기 위해 지식 베이스를 활용할 수 있는 챗봇을 만드는 방법을 다룹니다.

![image.png](https://prod-files-secure.s3.us-west-2.amazonaws.com/b70dea2a-0f0a-44d5-ae81-89a1124d77c1/82f305c3-c0c5-48f2-9daf-622a0f636ef0/image.png)

이러한 유형의 챗봇을 일반적으로 **검색 증강 생성(RAG)** 챗봇이라고 합니다. 핵심 구조는 이전 예제의 사용자 입력, LLM 호출, 지시사항 노드를 유지하되, 중요한 추가사항인 **지식 DB 검색** 노드가 추가되는 것입니다. 파란색 데이터 흐름 선에서 볼 수 있듯 사용자의 프롬프트는 이제 이 새로운 노드와 메인 LLM 호출 노드 모두에 전달됩니다.

지식 베이스 검색 노드는 사용자의 프롬프트를 기반으로, 미리 구축된 지식 베이스에서 관련 정보를 검색합니다. 검색된 지식은 LLM 호출 노드의 `지식` 입력으로 연결되어 주입됩니다. 이 프로세스는 사용자의 쿼리에 특화된 도메인 지식으로 LLM의 응답을 생성할 때 효과적입니다. 사용자의 초기 쿼리에 대한 응답을 생성할 때 LLM은 이 검색된 지식을 활용하도록 지시받습니다.

여기서 두 개의 노드가 더 추가됩니다. 첫 번째인 **사용자에게 메시지**는 사용자에게 시작 메시지를 보내는 노드입니다. 메인 루프 밖에 위치하기 때문에 이 메시지는 대화를 시작하는 소개 메시지로 처음 한 번만 전송됩니다. 두 번째 추가사항은 **프롬프트 버튼** 노드입니다. 이를 통해 사용자가 선택할 수 있는 초기 추천 또는 제안 프롬프트 세트를 지정할 수 있어, 특히 도메인 특화 또는 지식 기반 챗봇에서는 더욱 사용자 친화적인 경험을 제공합니다.

이러한 지식 기반 챗봇 플로우 그래프는 HyperFlow가 외부 지식을 활용하여 양질의 응답 생성하고 더욱 편리한 사용자 경험을 제공하는 정교한 챗봇을 만들 수 있는 능력을 보내줍니다.

### **예제 4: 지식 베이스 구축**

맞춤형 지식 기반 애플리케이션을 개발하는 데 있어 지식 베이스를 만들고 관리하는 것은 매우 중요합니다. HyperFlow에서는 이를 지원하는 데 필수적인 워크플로우를 만들 수 있습니다. 이번 예제에서는 이러한 지식 베이스를 구축하기 위해 설계된 워크플로우를 살펴봅니다.

![image.png](https://prod-files-secure.s3.us-west-2.amazonaws.com/b70dea2a-0f0a-44d5-ae81-89a1124d77c1/f674f2f7-74f9-474d-8b40-6cd809e40012/image.png)

이 플로우 그래프는 1) 콘텐츠 가져오기, 2) 관리 가능한 지식 청크로 나누기, 3) & 4) 검색 가능한 지식 베이스 구축 순서의 워크플로우로 설계하였습니다. 이는 HyperFlow가 단순 대화형 챗봇을 구현하는 것을 넘어서는 워크플로우를 만드는 데 어떻게 사용될 수 있는지 보여주는 좋은 예시입니다.

지식 데이터베이스 구축 플로우의 끝에는 작은 테스트 루프가 포함됩니다. 이 루프에서는 새로 구축된 지식 베이스를 테스트할 수 있습니다. 테스트 루프에서 사용자 프롬프트가 입력되고, 지식 베이스에 대한 검색이 수행되며, 결과가 표시되고 더 많은 테스트 쿼리를 위해 다시 루프백됩니다. 이 테스트 루프를 통해 구축된 지식 베이스의 정확성 및 효과성을 빠르게 확인 해 볼 수 있습니다.

지식 베이스를 구축하고 이를 테스트하는 워크플로우를 살펴봤으며, HyperFlow의 기능이 챗봇 개발에 국한되어있지 않으며 AI 애플리케이션 구축에 필요한 다양한 작업을 지원 할 수 있다는 것을 잘 보여줍니다.

### **예제 5: 이미지 생성 및 개선을 위한 에이젠틱 워크플로우**

이번엔 앞서 살펴본 챗봇과 지식 데이터베이스와는 조금 다른 유형인, **에이젠틱**  워크플로우를 살펴봅시다. 이 플로우 그래프는 두 개의 대형 언어 모델(LLM)이 협력하여 반복적인 이미지 생성 및 개선과 같은 다소 복잡한 작업을  수행하는지 설명합니다.

![image.png](https://prod-files-secure.s3.us-west-2.amazonaws.com/b70dea2a-0f0a-44d5-ae81-89a1124d77c1/dc583376-f5ac-4ec8-96e7-47513c84e11f/image.png)

이 플로우그래프의 핵심은 사용자의 요청을 기반으로 이미지를 생성하는 첫 번째 LLM과 그 이미지를 비평하고 개선하는 두 번째 LLM을 사용하는 것입니다. 가장 먼저, 사용자가 원하는 이미지를 설명하는 프롬프트를 제공하는 것으로 시작합니다. 이 프롬프트는 첫 번째 LLM에 전달되며, 이 모델은 DALL-E 3 또는 Stable Diffusion과 같은 이미지 생성이 가능한 모델을 사용합니다. 첫 번째 LLM은 사용자의 프롬프트를 바탕으로 첫 이미지를 생성합니다.

이렇게 생성된 이미지는 두 번째 LLM에 입력으로 전달됩니다. 이 두번째 LLM은, 최초로 생성된 이미지를 원래의 사용자 프롬프트와 함께 비교하여 검토하도록 지시합니다. 만약 이미지가 프롬프트에서 제시된 기준과 완전히 일치하지 않으면, 두 번째 LLM은 사용자의 최초 프롬프트에 더 잘 맞도록 개선된 이미지를 생성할 프롬프트를 다시 작성하는 임무를 맡습니다.

이렇게 다시 작성된 프롬프트는 다시 첫 번째 LLM에 전달되어 피드백 루프를 형성합니다. 첫 번째 LLM은 수정된 프롬프트를 기반으로 새로운 이미지를 생성하며, 이 과정은 반복됩니다. 즉, 사용자가 특정 이미지를 요청하면, 이 에이전틱 시스템은 루프에 들어가며, 매 회 루프가 반복 될 때마다 생성된 이미지를 개선하는 것을 목표로 합니다. 첫 번째 LLM은 이미지 생성기로 수정된 프롬프트에 응답하고, 두 번째 LLM은 비평자로서 이미지를 평가하고 프롬프트 수정을 제안합니다.

이 플로우 그래프는 여러 LLM이 협력하여 각자 특정 역할을 수행하며, 원하는 작업을 달성하는 전형적인 에이전틱 워크플로우를 보여주는 좋은 예시입니다. 이 경우에는 반복적인 개선을 통해 개선된 콘텐츠를 생성하는 플로우 그래프를 살펴보았습니다. 간단한 예시이지만, 여러 AI 에이전트의 협력적인 노력을 통해 복잡한 프로세스를 자동화하는 에이전틱 워크플로우의 강력한 기능을 보여줍니다.

### **예제 6: 자동화된 콘텐츠 묶음 처리**

이번엔  콘텐츠를 묶음처리하는 플로우그래프를 소개합니다. 이 예시는 HyperFlow가 챗봇 구축에만 제한되어있지 않음을 잘 보여줍니다. 이 유형의 워크플로우는 대규모 데이터를 처리하고 반복적인 작업을 자동화하는 데 유용할 수 있습니다.

![image.png](https://prod-files-secure.s3.us-west-2.amazonaws.com/b70dea2a-0f0a-44d5-ae81-89a1124d77c1/c9035711-1c40-4e61-a120-1e3006fca0fc/image.png)

이 플로우그래프를 통해 여러 개의 스캔된 이미지들을 처리해 보고자 합니다. 우선, 이 스캔된 이미지들을 묶음으로 가져오는 것부터 시작하고, 그 후에 각 이미지들은 하나씩 처리됩니다. 이미지를 하나씩 처리하기 위해서는 순차적으로 LLM으로 합니다. LLM은 이미지에 포함된 텍스트를 추출하기 위해 광학 문자 인식(OCR)을 수행하거나, 설명 요약을 생성하거나, 이미지에 손으로 쓴 메모나 다른 형태의 텍스트가 있을 경우 이를 기록할 수 있습니다.

LLM에서 나온 출력물(텍스트, 설명, 또는 기록된 내용)은 이후 ‘콘텐츠 추가’ 노드로 전달되며 이 출력물은 프로젝트의 자산 저장소에 저장됩니다. 이후의 워크플로우는 배치 내에서 다음 이미지 처리를 위해 루프를 돌아가며, 모든 항목이 처리될 때까지 계속됩니다. ‘루프 제어’ 노드는 데이터 묶음처리 노드와 협력하여, 배칭 노드의 입력이 모두 처리되었을 때 루프가 종료됩니다.  

이 플로우그래프는 HyperFlow 내에서 구현된 묶음 처리 루프의 예시로, 콘텐츠 처리 및 관리를 위해 최적화되어 있습니다. 이는 HyperFlow가 인터랙티브 챗봇을 넘어, AI 기술 관련 작업 자동화와 보다 광범위한 AI 애플리케이션 구축을 지원하는 다양한 워크플로우를 만드는 데 활용될 수 있음을 강조합니다.

### **예제 7: 도구(Tool)를 적용한 LLM을 사용해 챗봇 만들기**

이번 예시는 HyperFlow에서 도구를 활용하여 LLM을 워크플로우에 통합하는 지원 기능을 구현한 예제입니다. 이 기능을 통해 LLM은 외부 도구를 활용하여 기능을 확장하고 더욱 향상된 대답을 도출할 수 있습니다.

![image.png](https://prod-files-secure.s3.us-west-2.amazonaws.com/b70dea2a-0f0a-44d5-ae81-89a1124d77c1/7d9f0f8a-18d4-448e-a939-8e73a2f9ec71/image.png)

이 플로우그래프에서는 LLM이 사용자 프롬프트를 평가하여 특정 도구의 사용이 도움이 될지 판단할 수 있습니다. 해당 예시는 두 가지의 도구가 정의된 시나리오로, 실시간 날씨 정보를 가져오는 도구와 수학 계산을 수행하는 도구가 있습니다.

LLM은 사용자의 프롬프트를 평가하여, 프롬프트 내용에 더욱 정확하며 관련있는 응답을 제공할 수 있는 도구를 판단합니다. 특정 도구가 적절하다고 판단되면, LLM은 필요한 데이터를 제공하며 LLM 도구 에이전트 노드에 해당 도구 호출을 요청합니다. 예를 들어, 사용자가 특정 지역의 날씨에 대해 문의하면, LLM은 날씨 정보 도구의 관련성을 인식하고, 요청된 위치 정보를 입력으로 전달하여 최신 날씨 데이터를 가져옵니다. 마찬가지로, 프롬프트에 수학적 문제가 포함된 경우, LLM은 계산 도구를 사용해 답을 도출합니다.

도구를 활용하는 LLM을 루핑 챗봇 구조와 통합한 것은 에이전트 기반 AI 애플리케이션의 전형적 사례입니다. 이 예시는 LLM이 외부 기능으로부터 보완받아 그 기능을 확장할 수 있음을 잘 보여줍니다.
